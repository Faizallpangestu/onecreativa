# Read-only audit and migration review

Run `php check_counts.php` from the repository root with explicit `DB_HOST`, `DB_USER`, `DB_PASS`, `DB_NAME` environment variables (`DB_PORT` optional, default 3306). Use a SELECT-only database identity with metadata visibility. Empty passwords must still be explicitly supplied. The audit never loads application configuration, migration installers, or schema services. It starts a read-only consistent snapshot and rolls it back. No production audit or migration is performed by installing these files.

To export the review, redirect stdout to a local review file and check the process exit code before using it. Exit 1 means connection/query/schema failure; stdout contains no partial report. Exit 0 means queries completed, **not** that the accounts passed review. Missing tables are reported as MISSING; missing required columns fail the audit. Keep exports private and retain the timestamp and environment identity separately (without credentials).

The audit inventories historical income/expense, legacy adjustments, actual posted-journal linkage, unknown/NULL statuses, missing proof references and historical dates without an open period. Legacy coverage uses `accounting_transactions.legacy_finance_id` and the actual posted journal; manual journals or certified opening balances require separate evidence and are not automatically credited as coverage. A linked journal does not establish correct amounts, accounts or complete source coverage. An empty balanced ledger does not establish completeness.

For each historical record, the finance reviewer must record source ID/date/amount, verified evidence, approved classification, approved debit/credit accounts, approved bank identity, journal or opening-balance disposition, reviewer and approval reference. This tool supplies no invented COA mappings. A missing proof reference is a gap; an existing URL or attachment key does not establish that evidence is accessible or authentic.

Before migration, approve the cutover date and choose historical posting versus certified opening balances, with a boundary preventing double counting. Review closed/missing historical periods without automatically reopening them or moving dates. Reconcile source totals, bank, receivables, payables, taxes and opening balances independently. Adjustment inventory is not proof that every adjustment still needs migration. No importer or executable migration SQL is produced here.

Run the focused database-free regression with `php tools/audit-readonly-test.php`. It deliberately prints an AUDIT FAILED diagnostic while testing the nonzero failure path, then prints PASS. Existing accounting integration tests create databases and fixtures; they are not part of this read-only verification.
